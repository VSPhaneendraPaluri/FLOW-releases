overview

Separate simulation intent from ISA knowledge.

Write what you want to run in a small .flow script. Describe your ISA in YAML or as a compiled plugin. FLOW handles legal operand selection, constraint enforcement, and reproducible random draws — your ISA definition never needs to change.

Every new ISA starts the same way: a simulation model is ready, but the stimulus isn’t. Writing directed sequences by hand is slow, error-prone, and doesn’t scale to constrained-random testing. A new SoC variant shouldn’t mean weeks of re-authoring test scaffolding.

FLOW ends that cold-start.

ISA-agnostic by design

FLOW never hard-codes mnemonics, register counts, or encoding rules. Every ISA detail arrives at runtime through a plugin — the same engine runs your RISC-V, custom VLIW, or proprietary microcontroller ISA without recompilation. No engine build from source required.

Reproducible by contract

Pass --seed and get the exact same stream every time, across machines and runs. Determinism is enforced at the engine level — plugins cannot introduce hidden randomness. Bit-identical output in CI, by design.

integration

Built for your stack.

FLOW assembly output connects directly to the simulators, assemblers, and virtual platforms you already use — no adapters, no glue scripts.

RISC-V

Any RISC-V variant

Describe a RISC-V base ISA or custom extension set in YAML. Standard and non-standard extensions coexist in the same plugin. Under an hour to a working Tier‑A plugin.

SystemC / TLM2

VP stimulus generation

The Tier-3 encode hook produces byte streams your TLM2 initiator socket can consume directly — no assembler, no post-processing. FLOW plugs into your virtual platform’s stimulus path.

Virtual platforms

Spike · QEMU · gem5

Pipe assembly output through your assembler and feed it to any instruction-set simulator. FLOW is simulator-neutral — the script layer never sees the target platform.

ELF pipeline

Assemble, link, and run

FLOW emits standard assembly text. Run your toolchain assembler, link with a minimal runtime, and execute on the target — real silicon or model alike.

CI pipelines

Bit-identical regression

Pass --seed and every run produces the exact same stream. Deterministic output is enforced at the engine level. Diff your golden output — FLOW’s output never drifts.

Custom ISAs

VLIW · DSP · proprietary

No ISA knowledge is baked into the engine. VLIW, DSP, and proprietary microcontroller ISAs are first-class citizens through the same plugin API.

adoption ladder

Start at the tier you need.

Four integration tiers, ordered by the C++ you must write. Begin at the lowest tier that covers your ISA; move up only when you need more control. Most ISAs start and stay at Tier A.

A
no C++ Start here

YAML only

Describe your ISA entirely in instructions.yml and registers.yml. No compilation needed. Under an hour to running output.

B
minimal C++

YAML + encode

Add encodeInstruction() for split immediates, PC-relative branch targets, or packed encoding fields.

C
moderate C++

+ validate

Override validateOperands() for register write-protection, pipeline hazard rules, or pairing constraints.

D
full C++

IsaDefinition

Subclass IsaDefinition directly for maximum control: exotic encodings, instruction side effects, grammar extensions.

quick start

Running in minutes.

Tier A — no C++

Zero-C++ path

Place two YAML files in a directory and point FLOW at it. No compiler, no build step. The fastest path to running output.

1
Create a directory with two YAML files
directory layout
my_isa/ instructions.yml registers.yml
2
Run FLOW against your script
terminal
flow --isa-dir my_isa/ tests/smoke.flow
Tier B–D — compiled plugin

Compiled plugin path

Build your ISA as a shared library with the provided CMake helper, then load it at runtime. No engine rebuild required.

1
Register your ISA in CMakeLists.txt
CMakeLists.txt
flow_add_yaml_isa(myisa ${CMAKE_CURRENT_SOURCE_DIR}/data )
2
Build the plugin
terminal
cmake --build build
3
Run FLOW with the compiled plugin
terminal
flow --plugin build/myisa.so script.flow

Three workflow roles

my_isa.so / data/*.yml

ISA plugin author

Write the instruction table, register file, and optional encoding hooks. Your plugin is entirely your own work under MIT headers — no engine license obligations.

<name>.rules

Simulation architect

Define the constraint envelope: reserved registers, global instruction mix ratios, and locked constraints that apply across all scripts for a given simulation campaign.

<name>.flow

Script author

Express simulation intent through directed sequences, constrained-random draws, loops, and scenes — without touching the ISA definition or the constraint envelope.

reference

CLI options.

Both flow and flow_validate are single-binary tools. No runtime dependencies beyond the ISA plugin you supply.

OptionDescription
--plugin <path>Load a compiled ISA plugin (.so / .dll)
--isa-dir <path>Load a pure-YAML ISA from a directory (instructions.yml + registers.yml required)
--isa <name>Override ISA name (default: taken from script or YAML)
--seed <n>Fix the RNG seed for reproducible, bit-identical output
--count <n>Number of instruction sequences to generate
--output <file>Write output to file (default: stdout)
--helpPrint usage

--plugin and --isa-dir are mutually exclusive; --plugin takes precedence when both are given.
